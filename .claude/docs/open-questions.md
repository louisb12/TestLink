### 5. First-deploy checklist — four things only a real deployment can settle

I have no Mintlify account access, so these could not be closed here. All four clear in one
pass on the first preview deploy.

1. **Motion layer.** Custom `@keyframes` in a content-directory `.css` file **works** —
   verified properly with computed styles and `getAnimations()` in headless Chrome, not just
   "the file is served" (D-001). But Mintlify never documents it and behaviour can differ from
   `mint dev`. If it fails in production, motion reduces to CSS transitions plus Tailwind's
   stock utilities — a real but contained loss.
2. **`/llms.txt`, `/llms-full.txt`, `/mcp`.** All 404 locally — they are generated by the
   hosting layer, not the dev server (D-024). `contextual` is configured and validates, but
   the endpoints are **unverified**. The brief makes functional verification a launch
   requirement: point an agent at `/mcp` and ask it a real integration question. "The endpoint
   responds" is not verification.
3. **`mint score`.** Needs a deployed URL or an authenticated session; I did not run
   `mint login` unasked (D-025). **Not run.**
4. **Page `.md` suffixes.** Also deploy-time only, so the raw-Markdown-per-page behaviour is
   likewise unverified here.
